# Task: Database Metrics Collection

---

## Task Metadata

**Task Name**

Database Metrics Collection

**Description**

采集 PostgreSQL 数据库实例的八项核心性能指标，包括活跃会话数、缓冲池命中率、锁等待会话数、每秒事务数、主从复制延迟、死元组比例、后端写入缓冲区占比、事务空闲未关闭连接数，用于数据库健康巡检和性能诊断。

该任务依赖数据库指标采集工具从 pg_stat_activity、pg_stat_database、pg_stat_user_tables、pg_stat_bgwriter、pg_stat_replication 等系统视图获取真实指标数据，不允许依赖模型已有知识编造数据。

---

## Task Objective

完成用户的数据库性能指标采集请求，并返回结构化的指标数据与分析结论。

完成任务需要满足以下条件：

- 正确识别用户需要采集的数据库实例地址和数据库名称；
- 使用指标采集工具获取八项核心性能指标；
- 对返回的指标数据进行解读，指出异常指标并给出优化建议。

## Task Knowledge

### 数据库实例识别

用户可能采用以下方式描述数据库实例：

- 帮我采集 localhost:5432 上 mydb 库的性能指标
- 看看 192.168.1.100:5432/test_db 的数据库健康状况
- 巡检一下生产库 10.0.0.50:5432/order_db

如果用户未明确提供数据库实例地址或数据库名，应向用户询问。

不得自行猜测数据库连接信息。

### 八项指标说明

#### 1. 活跃会话数（Active Sessions）

统计当前正在执行查询的后端进程数量。

- **正常范围**：取决于业务并发量，通常 < CPU 核数 × 2
- **告警阈值**：持续超过 CPU 核数 × 4 需关注
- **异常原因**：慢查询堆积、锁等待连锁反应、连接池配置过大

#### 2. 缓冲池命中率（Buffer Cache Hit Rate）

共享缓冲区（shared_buffers）的缓存命中率。

- **正常范围**：> 95%
- **告警阈值**：< 90%
- **异常原因**：shared_buffers 设置过小、大量冷数据扫描挤出热数据、全表扫描频繁

#### 3. 锁等待会话数（Lock Waiting Sessions）

因无法获取表级锁或行级锁而处于等待状态的会话数。

- **正常范围**：0
- **告警阈值**：> 0 即需关注
- **异常原因**：长事务未提交、DDL 操作阻塞业务查询、死锁

#### 4. 每秒事务数（Transactions Per Second, TPS）

自上次统计重置以来的平均每秒事务数（xact_commit + xact_rollback）。

- **正常范围**：取决于业务规模
- **告警阈值**：TPS 突然大幅下降需关注
- **异常原因**：数据库负载过高、锁竞争严重、I/O 瓶颈

#### 5. 主从复制延迟（Replication Lag）

主库视角下各从库的 WAL 复制延迟，或从库视角下的事务重放延迟。

- **正常范围**：接近 0 或 < 1MB
- **告警阈值**：持续增长或 > 100MB
- **异常原因**：网络带宽不足、从库 I/O 性能差、大事务导致 WAL 堆积

#### 6. 死元组比例（Dead Tuple Ratio）

表中已删除/已更新但尚未被 VACUUM 回收的元组占比。

- **正常范围**：< 10%
- **告警阈值**：> 20%
- **异常原因**：VACUUM 未及时执行或执行频率不足、大批量 DELETE/UPDATE 后未 VACUUM、长事务阻止 VACUUM 回收

#### 7. 后端写入缓冲区占比（Backend Write Buffer Ratio）

后端进程直接写入磁盘的缓冲区占所有缓冲区写入的比例。

- **正常范围**：< 10%
- **告警阈值**：> 30%
- **异常原因**：bgwriter 配置不合理（bgwriter_lru_maxpages 过小）、shared_buffers 过小导致缓冲区频繁换出

#### 8. 事务空闲未关闭连接数（Idle-in-Transaction Connections）

已开启事务（BEGIN）但长时间未提交或回滚的连接数。

- **正常范围**：0
- **告警阈值**：> 0 即需关注
- **异常原因**：应用程序未正确关闭事务、ORM 框架事务管理缺陷、网络中断导致连接残留

## Task Workflow

执行当前任务时，应遵循以下流程：

### Step 1

分析用户请求。

判断是否明确包含以下信息：

- 数据库实例地址（host:port）
- 数据库名称

---

### Step 2

如果缺少数据库实例地址或数据库名：

结束当前执行，

询问用户提供缺失的连接信息。

不得调用工具。

---

### Step 3

确认以上信息均已获取：

调用数据库指标采集工具。

---

### Step 4

等待工具返回结果。

根据返回结果进行解读：

- 逐项检查八项指标是否在正常范围内；
- 对异常的指标，结合指标说明中的"异常原因"给出排查建议；
- 如果 metrics 中某项包含 error 字段，向用户说明该指标采集失败及原因；
- 对整体健康状况给出综合评价（健康 / 需关注 / 异常）。

不得修改工具返回的原始数据。

---

### Step 5

如果工具返回 success: false：

告知用户采集失败及失败原因，

建议检查数据库连接信息和网络可达性后重试。

## Tool Specification

当前任务可使用如下工具。

### Tool

name

collectDatabaseMetrics

description

采集PostgreSQL数据库实例的八项核心性能指标：活跃会话数、缓冲池命中率、锁等待会话数、每秒事务数、主从复制延迟、死元组比例、后端写入缓冲区占比、事务空闲未关闭连接数

### Parameters

```json
{
  "instance": "string",
  "database": "string"
}
```

参数说明：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| instance | string | 是 | 数据库实例地址，格式为host:port，例如：localhost:5432 |
| database | string | 是 | 数据库名称 |
