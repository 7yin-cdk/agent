# 长期记忆模块 分模块实现方案

> 依据：`docs/长期记忆模块设计方案.md`（设计定稿，含四类记忆、抽取机制、召回方式、混合保存策略）。
> 本文是**可逐个落地**的实现清单：实现顺序即模块编号顺序，每个模块有独立产出与验收标准，全部完成后做整体回归。

## 〇、模块总览

| 模块 | 名称 | 主要产出 | 依赖 | 验收要点 |
|---|---|---|---|---|
| M1 | 存储层 | DDL、实体、枚举、TypeHandler、Mapper | 无 | 建表成功、关键 SQL 可跑 |
| M2 | DTO 与配置 | DTO×5、Properties、yaml 配置块 | M1 | 配置可加载 |
| M3 | 核心服务 | LongTermMemoryService(Impl) | M1、M2 | 抽取/召回/去重/淘汰单元可调 |
| M4 | 对话链路接入 | AgentChatContext、PromptBuilder、RagService(Impl)、AgentServiceImpl、ReactiveStreamingService | M3 | 三条聊天链路 prompt 正确注入 |
| M5 | 管理接口 | LongTermMemoryController | M3 | CRUD 全通 |
| M6 | 集成收尾 | 建表执行、整体回归、定时任务验证 | M1–M5 | 设计文档 §七 验收清单全过 |

依赖链：`M1 → M2 → M3 → M4/M5 → M6`。M4 与 M5 无相互依赖，可并行开发。

## 模块一：存储层

**目标**：建好 `agent_long_term_memory` 表与全部索引，提供完整的数据访问能力。

### 1.1 DDL — 新增 `src/main/resources/db/agent_long_term_memory.sql`

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE IF NOT EXISTS agent_long_term_memory (
    id                    BIGSERIAL PRIMARY KEY,
    user_id               VARCHAR(64)  NOT NULL,
    category              VARCHAR(32)  NOT NULL,               -- USER_PROFILE/PREFERENCE/CONSTRAINT/ENTITY/EXPERIENCE
    content               TEXT         NOT NULL,
    keywords              TEXT[]       NOT NULL DEFAULT '{}',
    entity                VARCHAR(255),
    entity_type           VARCHAR(64),
    embedding             VECTOR(1536),
    importance            SMALLINT     NOT NULL DEFAULT 5 CHECK (importance BETWEEN 1 AND 10),
    confidence            DOUBLE PRECISION NOT NULL DEFAULT 0.8,
    dedup_key             VARCHAR(128),
    access_count          INTEGER      NOT NULL DEFAULT 0,
    last_accessed_at      TIMESTAMPTZ,
    source_conversation_id VARCHAR(64),
    source_turn           VARCHAR(128),
    metadata              JSONB        NOT NULL DEFAULT '{}'::jsonb,
    is_deleted            BOOLEAN      NOT NULL DEFAULT FALSE,
    expired_at            TIMESTAMPTZ,
    created_at            TIMESTAMPTZ  NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at            TIMESTAMPTZ  NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE UNIQUE INDEX IF NOT EXISTS uk_ltm_dedup
    ON agent_long_term_memory (user_id, dedup_key)
    WHERE dedup_key IS NOT NULL AND is_deleted = FALSE;

CREATE INDEX IF NOT EXISTS idx_ltm_user_category
    ON agent_long_term_memory (user_id, category, importance DESC);
CREATE INDEX IF NOT EXISTS idx_ltm_user_updated
    ON agent_long_term_memory (user_id, updated_at DESC);
CREATE INDEX IF NOT EXISTS idx_ltm_entity
    ON agent_long_term_memory (user_id, entity);
CREATE INDEX IF NOT EXISTS idx_ltm_entity_type
    ON agent_long_term_memory (user_id, entity_type);
CREATE INDEX IF NOT EXISTS idx_ltm_keywords
    ON agent_long_term_memory USING GIN (keywords);
CREATE INDEX IF NOT EXISTS idx_ltm_evict
    ON agent_long_term_memory (user_id, category, importance ASC,
                               last_accessed_at ASC NULLS FIRST, access_count ASC)
    WHERE is_deleted = FALSE;
CREATE INDEX IF NOT EXISTS idx_ltm_embedding_hnsw
    ON agent_long_term_memory USING hnsw (user_id, embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 200);
```

要点：
- `embedding VECTOR(1536)` 与现有 `FloatArrayTypeHandler` 的 1536 维强校验一致（text-embedding-v4）。
- 多列 HNSW 依赖 pgvector ≥ 0.5；低版本退化为单列 `(embedding vector_cosine_ops)`（每用户数据量小，可接受）。
- `entity` 作为实体挂载点，非必填；ENTITY 类记忆应填写。

### 1.2 实体 — 新增 `entity/AgentLongTermMemory.java`

`@Data` 风格（同 `AgentShortTermMemory`）。字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long | BIGSERIAL |
| userId | String | 与现有 user_id 同型 |
| category | String | MemoryCategory 常量 |
| content | String | 记忆正文（自包含、无指代） |
| keywords | List\<String\> | TEXT[] |
| entity / entityType | String | 实体名 / 类型 |
| embedding | float[] | 1536 维 |
| importance | Integer | 1–10 |
| confidence | Double | 0–1 |
| dedupKey | String | 去重键 |
| accessCount / lastAccessedAt | Integer / LocalDateTime | 淘汰用 |
| sourceConversationId / sourceTurn | String | 溯源 |
| metadata | Map\<String, Object\> | JSONB（如 EXPERIENCE 的 result） |
| deleted | Boolean | 逻辑删除 |
| expiredAt | LocalDateTime | 显式过期 |
| createdAt / updatedAt | LocalDateTime | |
| similarity（transient） | Double | 仅向量召回填充，不落库 |

### 1.3 枚举 — 新增 `enums/MemoryCategory.java`

`USER_PROFILE / PREFERENCE / CONSTRAINT / ENTITY / EXPERIENCE`（风格同 `IntentType`）。

### 1.4 TypeHandler — 新增 `handler/StringArrayTypeHandler.java`

`BaseTypeHandler<List<String>>`：`setNonNullParameter` 用 `ps.getConnection().createArrayOf("text", arr)`；`getNullableResult` 用 `rs.getArray(col).getArray()` 还原。现有 handler 目录无数组 handler，需新建。

### 1.5 Mapper — 新增 `mapper/AgentLongTermMemoryMapper.java` + `resources/mapper/AgentLongTermMemoryMapper.xml`

接口方法（`@Mapper` + `@Param`，风格同 `AgentShortTermMemoryMapper`）：

```
insert(memory)                          -- 基础插入
selectById(userId, id)                  -- 详情（is_deleted=FALSE）
selectByDedupKey(userId, dedupKey)      -- 去重查询
selectPage(userId, category, entity, offset, size)  -- 管理分页（可带分类/实体过滤）
countByUser(userId, category, entity)   -- 分页 total
selectAlwaysOn(userId, limit)           -- USER_PROFILE/PREFERENCE/CONSTRAINT，importance 排序
selectByEntities(userId, entities, keywords, limit) -- 实体等值 + keywords 重叠
selectTopKByEmbedding(userId, embedding, topK)      -- 向量召回（EXPERIENCE）
updateAccessCount(userId, id)           -- access_count+1, last_accessed_at=now
updateContent(memory)                   -- 冲突消解后全量更新（含重算 embedding）
updateImportance(userId, id, importance)
countByCategory(userId, category)       -- 容量统计
selectEvictCandidates(userId, category, limit)      -- 淘汰候选
logicalDeleteById(userId, id) / logicalDeleteByCategory(userId, category) / logicalDeleteByUser(userId)
physicalDeleteByIds(ids)                -- 淘汰物理删除
deleteExpired()                         -- 清理过期且已逻辑删除的行
```

XML 关键点：
- resultMap：`embedding` 用 `FloatArrayTypeHandler`、`metadata` 用 `JsonbTypeHandler`、`keywords` 用 `StringArrayTypeHandler`。
- 向量召回：`WHERE user_id=? AND is_deleted=FALSE AND (expired_at IS NULL OR expired_at > CURRENT_TIMESTAMP) AND category IN ('EXPERIENCE') ORDER BY embedding <=> ? LIMIT ?`，同时 `SELECT 1-(embedding <=> ?) AS similarity`。
- 实体等值：`AND (entity IN (...) OR keywords &amp;&amp; ARRAY[...]) ORDER BY importance DESC`（**`&&` 必须转义 `&amp;&amp;`**）。
- 淘汰候选：`ORDER BY importance ASC, last_accessed_at ASC NULLS FIRST, access_count ASC LIMIT ?`。

### 模块一验收

1. 在 `rag_db` 执行 DDL，`\d agent_long_term_memory` 确认字段与索引齐全。
2. `EXPLAIN` 确认向量召回 SQL 命中 hnsw 索引。
3. 手工插入一条带向量 + JSONB + 数组的记录，各查询方法可正确返回（尤其向量、JSONB、数组字段还原）。

## 模块二：DTO 与配置

**目标**：定义服务层与接口层的数据载体，并把参数抽成可配置项。

### 2.1 DTO — 新增 `memory/dto/` 下 5 个类

- `LongTermMemoryCandidate`：category/content/keywords/entity/entityType/importance/confidence/dedupKey（抽取与手动添加共用）。
- `MemoryView`：展示 VO，**剔除 embedding**，含可选 similarity。
- `MemoryPageResponse`：`{long total; int page; int size; List<MemoryView> items;}`。
- `MemoryAddRequest`：category/content/keywords/entity/entityType/importance/confidence/expiredAt。
- `MemoryUpdateRequest`：content/importance/confidence/category/entity/keywords/expiredAt 全可选。

### 2.2 配置类 — 新增 `config/LongTermMemoryProperties.java`

`@ConfigurationProperties(prefix = "agent.ltm")`，字段对应下方 yaml 全量参数。

### 2.3 配置 — 修改 `src/main/resources/application.yaml`（`agent:` 下新增）

```yaml
agent:
  ltm:
    always-on-limit: 5        # always-on 注入条数
    entity-recall-limit: 8    # 实体等值召回条数
    vector-top-k: 20          # 向量召回候选数
    rrf-limit: 10             # RRF 融合后候选数
    rerank-top-n: 3           # rerank 最终条数
    rerank-min-score: 0.3
    inject-limit: 6           # 最终注入 prompt 总条数上限
    capacity: { user-profile: 50, preference: 50, constraint: 50, entity: 200, experience: 200 }
    eviction: { cron: "0 17 3 * * *" }
    extraction: { min-turn-messages: 2 }
```

### 模块二验收

应用启动成功，`LongTermMemoryProperties` 注入有效，各参数可读到配置值（可临时在启动日志或单元测试中打印确认）。

## 模块三：核心服务

**目标**：实现长期记忆的全部业务逻辑——抽取、去重/冲突消解、召回、淘汰、CRUD。

### 3.1 接口 — 新增 `memory/LongTermMemoryService.java`

```java
void postTurn(Long userId, String conversationId, String userQuery,
              String assistantAnswer, List<AgentShortTermMemory> turnMessages, String sourceTurn);
void extractFromTurn(Long userId, String conversationId, String userQuery,
                     String assistantAnswer, List<AgentShortTermMemory> turnMessages, String sourceTurn); // @Async
AgentLongTermMemory store(Long userId, LongTermMemoryCandidate candidate);
List<AgentLongTermMemory> storeAll(Long userId, List<LongTermMemoryCandidate> candidates);
void recall(AgentChatContext context);
MemoryPageResponse page(Long userId, String category, String entity, int page, int size);
AgentLongTermMemory getById(Long userId, Long id);
AgentLongTermMemory update(Long userId, Long id, MemoryUpdateRequest request);
void deleteById(Long userId, Long id);
void deleteByCategory(Long userId, String category);
void deleteByUser(Long userId);
void evictIfNeeded(Long userId, String category);
void scheduledEviction();   // @Scheduled
```

### 3.2 实现 — 新增 `memory/impl/LongTermMemoryServiceImpl.java`

`@Service @RequiredArgsConstructor`，依赖 `AgentLongTermMemoryMapper`、`LlmService`、`ObjectMapper`、`LongTermMemoryProperties`。私有方法按职责拆分：

| 私有方法 | 职责 | 关键实现 |
|---|---|---|
| `isRememberCommand(query)` | 判显式"记住" | 正则 `(?i)^(请)?记住|记一下|请记下` |
| `buildExtractPrompt(...)` | 组装抽取 prompt | 见设计 §5.1；输入 user/assistant/tool 消息 |
| `parseCandidates(json)` | 解析 LLM 输出 | 定位首个 `[` 与末 `]` 截取 → `ObjectMapper.readTree` → List\<Candidate\>，缺省字段给默认值（importance=5、confidence=0.8、keywords=[]） |
| `dedupAndStore(candidate)` | 去重入库 | embed(content) → `selectByDedupKey` → 无则 insert；有则 `resolveConflict` |
| `resolveConflict(old,new)` | 冲突消解 | LLM 冲突消解 prompt（设计 §5.2）→ MERGE/REPLACE 调 `updateContent`（用合并后 content 重算 embedding，importance=max）；KEEP 仅 `updateAccessCount`；DELETE 逻辑删旧。EXPERIENCE 同问题不同结果保留两行（dedup_key 加 `#<n>`） |
| `recall(context)` | 回答前召回 | 四路取（见 3.3）→ 写入 `context.longTermMemories`；整体 try/catch fail-open |
| `evictIfNeeded(userId,category)` | 写入时淘汰 | `countByCategory` − 容量 = excess；excess>0 → `selectEvictCandidates` → `physicalDeleteByIds` |
| `scheduledEviction()` | 定时清扫 | `@Scheduled(cron=...)`：`deleteExpired()` + 全用户全分类容量复查 |
| `extractFromTurn` | 异步抽取入口 | `@Async`，异常 catch + log.warn（照抄 `ConversationSummaryServiceImpl` 模式） |

### 3.3 `recall(context)` 内部四路

1. **always-on**：`selectAlwaysOn(userId, alwaysOnLimit=5)`（USER_PROFILE/PREFERENCE/CONSTRAINT，无条件注入）。
2. **实体等值**：从 query/rewrittenQuery 正则抽取实体 token（`[\w.-]+(?:集群|库|表|实例|任务|索引)`、`(db|database|cluster|table|schema)[.\w]+`）→ `selectByEntities(userId, entities, keywords, 8)`。
3. **向量召回**：`llmService.embed(rewrittenQuery)` → `selectTopKByEmbedding(userId, vector, 20)`（EXPERIENCE）。
4. **融合**：路 2、3 结果走 RRF（复用 `RagServiceImpl.mergeByRrf` 的 `1/(60+rank)` 打分，取 10）→ `llmService.rerank(rewrittenQuery, chunks, 3, 0.3)`。
   最终 always-on(≤5) + reranked(≤3)，截断到 `injectLimit=6`；对选中 id 批量 `updateAccessCount`。

### 3.4 关键约定

- **所有对外入口 fail-open**：任何异常不得抛给主流程。
- **embedding 失败降级** `embedding=NULL` 存储（仍可 always-on/等值召回）。
- 抽取触发门槛：`turnMessages.size() < minTurnMessages(2)` 不触发。

### 模块三验收

1. `store` 一条候选：入库成功、embedding 非空、可查回。
2. 重复同 dedup_key 候选：走 MERGE（不新增行），content 更新、importance 取大。
3. `postTurn` 收到含"记住…"的查询：同步落库。
4. `recall` 对空库返回空列表且不抛异常；有数据时按四路召回并更新 access_count。
5. 灌超容量 EXPERIENCE 数据：最不重要/最久未访问的被淘汰。

## 模块四：对话链路接入

**目标**：把长期记忆接到现有聊天主流程——回答前召回注入 prompt，对话后异步抽取。

### 4.1 `context/AgentChatContext.java`

新增 `private List<AgentLongTermMemory> longTermMemories;`（承载召回结果）。

### 4.2 `llm/PromptBuilder.java`

- 新增私有 `appendLongTermMemory(StringBuilder, List<AgentLongTermMemory>)`：格式 `### 长期记忆` + `【记忆N】[类别] 内容`，**空列表整段省略**。
- `buildSimplePrompt`（L46-69）：增加带 memories 的重载，在 `appendConversationHistory` 之后调用。
- `buildRagPrompt`（L104-133）：同上，在 `appendRagTexts` 之后调用。
- `buildTaskPrompt`（L172-202）：替换链（L199-201）增加 `.replace("{{long_term_memory}}", buildLongTermMemoryText(context.getLongTermMemories()))`，并在 `Prompt/task/*.md` 或 `CurrentConversationStatePrompt.md` 预留占位符。

### 4.3 `rag/service/RagService.java` + `impl/RagServiceImpl.java`

`queryStream(...)`（RagService L44-60 / RagServiceImpl L120-132）、`buildRagPrompt(...)`（RagServiceImpl L134-175）：增加 memories 参数透传，`buildRagPrompt` 最终改调带 memories 的重载（原方法委托传 `List.of()`，保持兼容）。

### 4.4 `service/Impl/AgentServiceImpl.java`

- 注入 `LongTermMemoryService`。
- `chat()`（L74-121）：
  - `buildChatContext`（L94-102）之后、`route`（L103）之前：`longTermMemoryService.recall(context)`。
  - 保存消息（L105-112）之后、`triggerSummaryIfNeeded`（L115）之前：`longTermMemoryService.postTurn(userId, conversationId, query, answer, historyMessages, sourceTurn)`。
- `doChatStream()`（L187-242）：`buildChatContext`（L210-218）之后、`routeStream`（L221）之前插 `recall`；`routeStream` 之后插 `postTurn`。
- `routeStream()`（L244-281）：KNOWLEDGE_BASE 分支（L248）传 `context.getLongTermMemories()`；SIMPLE_CHAT 分支（L272）改用带 memories 的 `buildSimplePrompt`；COMPLEX_TASK 分支走 `buildTaskPrompt`（已含 memories）。

### 4.5 `service/ReactiveStreamingService.java`

- 注入 `LongTermMemoryService`。
- `doChatAndStream()`（L99-151）：`buildChatContext`（L126-128）之后、`routeStream`（L132）之前插 `recall`；保存消息后（约 L141 后、trace 前）插 `postTurn`。
- `routeStream()`（L159-209）：三分支同 4.4 透传 memories。

### 模块四验收

1. 有记忆时发起 `/agent/chat`，日志中 prompt 含 `### 长期记忆` 段且内容相关。
2. 无记忆时不含该段（不干扰 SIMPLE_CHAT）。
3. `/agent/chat`、`/agent/chat/stream`、`/agent/chat/reactive/stream` 三条链路行为一致。
4. 模拟召回/抽取抛异常：用户提问不受影响（fail-open）。

## 模块五：管理接口

**目标**：提供长期记忆的完整 CRUD REST API。

### 5.1 `memory/controller/LongTermMemoryController.java`

`@RestController @RequestMapping("/agent/memories")`，风格对齐 `ConversationController`（`UserContextHolder.getUserId()` 取当前用户；id 不存在或非本人 → 404；category 非法 → 400）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/agent/memories` | 分页列表（category/entity 可选过滤，page 默认1、size 默认20上限100） |
| GET | `/agent/memories/{id}` | 详情（剔除 embedding） |
| GET | `/agent/memories/search?query=&topK=` | 召回调试接口，返回带 similarity |
| POST | `/agent/memories` | 手动添加（复用 `store`，自动 embedding/去重/淘汰） |
| PATCH | `/agent/memories/{id}` | 修改（改 content 重算 embedding） |
| DELETE | `/agent/memories/{id}` | 逻辑删除单条 |
| DELETE | `/agent/memories?category=` | 按分类或全部逻辑删除 |

### 模块五验收

curl 走通全部接口：分页/过滤、详情、search 带 similarity、添加、修改、删除、按分类删除；验证 404/400 语义与 userId 隔离（其他用户 id 不可见）。
